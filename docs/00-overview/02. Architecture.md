# 02. Architecture

## Status

Draft — awaiting review. Describes the system shape and the locked design
decisions. Module-level contracts live in `docs/02-analysis-specs/`.

## Shape of the system

A **scheduled batch job**, not a running server. GitHub Actions runs the
pipeline weekly; the pipeline fetches data, analyzes it, renders a report, and
emails it. This preserves the predecessor's zero-infrastructure, free-tier
model.

```
GitHub Actions (weekly cron)
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│  PIPELINE (Python)                                            │
│                                                              │
│  1. INGEST                                                    │
│     • Ledger        ← Google Sheet (owner's, via service acct)│
│     • Prices        ← Yahoo Finance (no key)                  │
│     • Macro         ← FRED (free API key)                     │
│     • Fundamentals  ← SEC EDGAR (free) / Alpha Vantage (free) │
│     • News          ← RSS / Finnhub (free)                    │
│                                                              │
│  2. ANALYZE (deterministic, auditable)                        │
│     • Positions & P&L & currency effect                       │
│     • Portfolio risk & concentration                          │
│     • Macro & currency read                                   │
│     • Signal engine (upgraded technicals)                     │
│     • Opportunity scanner (sector ETFs)                       │
│                                                              │
│  3. NARRATE (optional LLM layer — Gemini free tier)           │
│     • Input: de-identified facts (percentages, dated news)    │
│     • Output: analyst narrative with evidence + limitations   │
│     • If disabled/unavailable → deterministic summary instead │
│                                                              │
│  4. RENDER  → HTML email (full, real amounts; built by Python)│
│  5. SEND    → Gmail API (owner's inbox)                       │
└─────────────────────────────────────────────────────────────┘
```

## Locked design decisions

### LLM access: Gemini **API key**, not the Plus subscription

The owner has a **Gemini Plus** subscription (the gemini.google.com app). That
is a *consumer chat product* and cannot be used by code. Code needs the
**Gemini API**, authenticated with an **API key** generated for free in Google
AI Studio. The two are separate products with separate billing.

- The Gemini API has its own **free tier** (e.g. a Flash model), which is more
  than enough for one report per week and does not touch the Plus subscription.
- The key is stored as a GitHub Secret (`GEMINI_API_KEY`), mirroring how
  `GMAIL_TOKEN_JSON` is handled in the predecessor.

### The owner's data lives in the owner's systems, never in the LLM

- An LLM is **stateless**: it has no memory between weekly calls and therefore
  **cannot** be a data store.
- Free-tier LLM input may be used for service improvement, so **no PII and no
  real amounts** are ever sent to it.
- **Source of truth = the owner's Google Sheet.** Python reads it, computes
  everything, and builds the full report locally.

### De-identification boundary

| Audience | Sees |
|----------|------|
| The owner's email (built by Python) | Everything: real IDR amounts, tickers, P&L |
| The LLM (narrative layer) | De-identified only: structure, percentages, dated news. e.g. "Position A: semiconductor ETF, −2.2%, 53% of portfolio" — never "SMH, Rp3.3M, −74k" |

### Ledger storage: owner's Google Sheet

- The owner records each **transaction** (buy/sell) in a personal Google Sheet,
  convenient to update from a phone.
- GitHub Actions reads it via a **Google service account** (read-only),
  credentials stored as a GitHub Secret.
- The system derives positions, average cost, realized/unrealized P&L, and the
  USD/IDR currency effect per transaction from this ledger.
- The Sheet schema (columns, types, example rows) is specified in
  `docs/01-data-sources/`.

## Data sources (all free tier)

| Source | Role | Auth | Limit (free, approx.) |
|--------|------|------|-----------------------|
| Yahoo Finance | Prices, technicals (already proven) | none | unofficial; fail-safe fallback |
| FRED | Macro: yields, yield curve, Fed, USD | free key | ~1,000 req/day |
| SEC EDGAR (XBRL) | Fundamentals (authoritative) | User-Agent header | unlimited |
| Alpha Vantage | Valuation shortcut (P/E, PEG) | free key | 25 req/day, 500/mo |
| Finnhub / RSS | News & sentiment | free key / none | news endpoints usable |
| Gemini API | Narrative analyst layer | free API key | enough for weekly use |

> Division of labor keeps everything free: Yahoo for prices (proven), FRED for
> macro, SEC EDGAR for fundamentals, Alpha Vantage as a valuation shortcut.
> Fundamentals do not rely on Yahoo (unstable for that use).

## Secrets (GitHub Actions)

Mirrors the predecessor's secret-based model. None of these are ever committed.

| Secret | Purpose |
|--------|---------|
| `GMAIL_TOKEN_JSON` | Send the digest (reused pattern) |
| `EMAIL_TO` | Recipient |
| `GOOGLE_SA_JSON` | Service account to read the ledger Sheet |
| `SHEET_ID` | The ledger Google Sheet ID |
| `FRED_API_KEY` | Macro data |
| `ALPHAVANTAGE_API_KEY` | Valuation data |
| `FINNHUB_API_KEY` | News/sentiment (optional) |
| `GEMINI_API_KEY` | Narrative analyst layer (optional) |

## Resilience

- Every external fetch is fail-safe: a failing source yields a flagged,
  partial result and a clear note in the report, never a crash (inherited from
  the predecessor).
- The LLM layer is **optional**: if `GEMINI_API_KEY` is absent or the call
  fails, the pipeline emits a deterministic rule-based summary and still ships
  the email.

## Branching & workflow

- Feature branches `feat/...` → `uat` → `main`.
- Contract-first: specs are written and reviewed before implementation; tests
  cover each spec's numbered "Test cases" 1:1.
- Repository artifacts (code, docs, commit messages, branches) are in English.

## Deferred (not in initial scope)

- Interactive dashboard (GitHub Pages / Streamlit).
- Reactive intraday alerting.
- Postgres-backed ledger (Neon) — only if transaction volume outgrows a Sheet.
