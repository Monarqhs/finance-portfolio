# 01. Setup Guide

One-time setup to make the weekly analyst email run on GitHub Actions. Nothing
here is committed; every sensitive value is a GitHub Secret.

## Overview of what you need

| Secret | What it is | Where it comes from |
|--------|------------|---------------------|
| `EMAIL_TO` | Where the report is sent | your email address |
| `SHEET_ID` | Your ledger Google Sheet ID | the Sheet URL |
| `GOOGLE_SA_JSON` | Service-account key (reads the Sheet) | Google Cloud |
| `FRED_API_KEY` | Macro data | fred.stlouisfed.org |
| `GEMINI_API_KEY` | Analyst narrative (optional) | Google AI Studio |
| `GMAIL_TOKEN_JSON` | Sends the email | Gmail OAuth (`token.json`) |

The pipeline is **fail-safe**: if an optional source (e.g. `GEMINI_API_KEY`) is
absent, the report still ships with a deterministic analyst note.

## 1. Create the ledger Google Sheet

1. Create a Google Sheet. Name the first worksheet **`transactions`**.
2. Put this header in row 1 (column order may vary; names must match):

   ```
   date | ticker | action | quantity | price_usd | fee_usd | usdidr | note
   ```

3. Record one row per transaction. Example:

   ```
   2026-09-15 | SMH  | BUY | 0.308  | 10983.87 | 0 | 17200 | tranche 1
   2026-09-29 | MU   | BUY | 0.0528 | 18812.14 | 0 | 17350 | tranche 1
   2026-10-06 | SKHY | BUY | 0.294  | 3399.05  | 0 | 17600 | new position
   ```

   See [`docs/01-data-sources/01. Ledger (Google Sheet).md`](../01-data-sources/01.%20Ledger%20(Google%20Sheet).md)
   for the full schema and the P&L rules.

4. The **Sheet ID** is the long string in the URL between `/d/` and `/edit`:
   `https://docs.google.com/spreadsheets/d/`**`THIS_IS_THE_ID`**`/edit`.

## 2. Service account to read the Sheet

1. In [Google Cloud Console](https://console.cloud.google.com/), create (or
   reuse) a project.
2. **APIs & Services → Library** → enable **Google Sheets API**.
3. **APIs & Services → Credentials → Create credentials → Service account**.
   Create it; no roles needed.
4. On the service account, **Keys → Add key → JSON** → download the file.
5. Open the JSON, copy the `client_email`, and **share your Sheet** with that
   email as **Viewer** (read-only).
6. The whole JSON file content becomes the `GOOGLE_SA_JSON` secret.

## 3. FRED API key (macro)

1. Create a free account at
   [fred.stlouisfed.org](https://fred.stlouisfed.org/) → **My Account → API Keys**.
2. Request a key. That string is `FRED_API_KEY`.

## 4. Gemini API key (optional narrative)

> This is the **API key**, not your Gemini Plus subscription — they are separate
> products. The API has its own free tier, enough for one report a week.

1. Go to [Google AI Studio → API keys](https://aistudio.google.com/apikey).
2. Create a key. That string is `GEMINI_API_KEY`.
3. Leave it unset to run without the LLM (deterministic note is used).

Note: the narrative layer only ever receives **de-identified** data
(percentages/structure), never your real amounts — see
[`docs/02-analysis-specs/05. Analyst Narrative (Gemini).md`](../02-analysis-specs/05.%20Analyst%20Narrative%20(Gemini).md).

## 5. Gmail send token

Reuses the predecessor's pattern (scope `gmail.send` only):

1. In Google Cloud, enable the **Gmail API** and create an **OAuth client ID**
   of type **Desktop app**; download `credentials.json`.
2. Produce `token.json` by running the one-time helper **on your own computer**
   (it opens a browser to log in and approve):

   ```bash
   pip install google-auth-oauthlib
   # put credentials.json in the current folder, then:
   python scripts/generate_gmail_token.py
   ```

   The full contents of the resulting `token.json` become the
   `GMAIL_TOKEN_JSON` secret. (Paste `token.json`, **not** `credentials.json` —
   the secret must contain a top-level `"refresh_token"`.)
3. If the OAuth consent screen is in **Testing** mode, publish the app
   (Audience → Publish) so the refresh token does not expire every 7 days.

> Security: `credentials.json` and `token.json` are git-ignored and must never
> be committed. If your `client_secret` is ever exposed, delete that OAuth
> client in Google Cloud and create a new one.

## 6. Add the GitHub Secrets

In the repo: **Settings → Secrets and variables → Actions → New repository
secret**, add each of the six secrets from the table above.

## 7. Run it

- **Manual test:** repo **Actions → weekly-digest → Run workflow**.
- **Automatic:** every Monday 00:00 UTC (07:00 WIB). GitHub only runs scheduled
  workflows from the **default branch** (`main`), so the schedule activates once
  this is merged to `main`.

## 8. Local preview (no secrets, no send)

```bash
pip install -e ".[dev]"
python -m analyst.main --preview   # writes preview.html
```

## Privacy reminder

Your ledger lives in your own Google Sheet; the pipeline reads it read-only and
builds the full email locally. The optional LLM only sees de-identified data.
Consider making the repository **private** if you want the configuration itself
kept out of public view.
