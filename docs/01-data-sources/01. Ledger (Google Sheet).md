# 01. Ledger (Google Sheet)

## Status

Draft — awaiting review. This is the **source of truth** for the owner's real
positions. It defines the Sheet schema and how the pipeline reads it.

## Role

The owner records every transaction (buy/sell) in a personal Google Sheet,
convenient to update from a phone. GitHub Actions reads it **read-only** via a
Google service account. From these transactions the pipeline derives positions,
average cost, realized/unrealized P&L, and the USD/IDR currency effect.

No amounts are ever committed to the repo; the Sheet lives in the owner's Google
account. Access uses `GOOGLE_SA_JSON` and `SHEET_ID` from GitHub Secrets.

## Why a ledger (transactions) and not a snapshot

A transaction ledger lets the system compute **realized P&L** and the
**currency effect per transaction** (each buy/sell carries the USD/IDR rate at
that moment). A static snapshot of current holdings cannot reconstruct either.

## Sheet schema

One worksheet named `transactions`. Row 1 is a header. One row per transaction.

| Column | Name | Type | Required | Notes |
|--------|------|------|----------|-------|
| A | `date` | date `YYYY-MM-DD` | yes | Trade date (execution). |
| B | `ticker` | text | yes | Yahoo symbol, e.g. `SMH`, `MU`, `SKHY`. |
| C | `action` | enum `BUY` / `SELL` | yes | Case-insensitive on read. |
| D | `quantity` | decimal | yes | Shares/units. Fractional allowed (e.g. `0.308`). Always positive. |
| E | `price_usd` | decimal | yes | Execution price per unit, in USD. |
| F | `fee_usd` | decimal | no | Commission/fees in USD. Default `0`. |
| G | `usdidr` | decimal | yes | USD/IDR rate at execution (from the broker/app). |
| H | `note` | text | no | Free text, e.g. "tranche 2", broker name. |
| I | `currency` | enum `USD` / `IDR` | no | Defaults to `USD`. Use `IDR` for rupiah-native rows (cash/RDPU, IDX stocks): `price_usd` then holds the per-unit IDR price and `usdidr` is not required (treated as 1, so no FX conversion and FX P&L is 0). |

### Example rows

```
date        ticker  action  quantity  price_usd  fee_usd  usdidr   note
2026-09-15  SMH     BUY     0.308     10983.870  0        17200    tranche 1
2026-09-29  MU      BUY     0.0528    18812.139  0        17350    tranche 1
2026-10-06  SKHY    BUY     0.294     3399.050   0        17600    new position
```

> owner's broker display; real values live only in the Sheet.

## Derivation rules (how transactions become positions)

Processed in `date` order, then by row order for same-day rows.

1. **Position quantity** = Σ BUY qty − Σ SELL qty, per ticker.
2. **Average cost (USD)** = cost basis of remaining shares, using the
   **weighted-average-cost** method:
   - On BUY: `cost_basis += quantity * price_usd + fee_usd`;
     `qty += quantity`; `avg_cost = cost_basis / qty`.
   - On SELL: realized against current `avg_cost`:
     `realized_usd += quantity * (sell_price - avg_cost) - fee_usd`;
     `qty -= quantity`; `cost_basis = avg_cost * qty` (avg_cost unchanged).
3. **Unrealized P&L (USD)** = `qty * (current_price - avg_cost)` using the
   latest price from the price source.
4. **Currency effect** is tracked separately so IDR P&L never silently mixes
   price moves with FX moves:
   - `cost_basis_idr` accumulates `quantity * price_usd * usdidr` on each BUY.
   - `market_value_idr = qty * current_price * usdidr_now`.
   - `asset_pnl_idr`  = price move only, held at entry FX (per-lot).
   - `fx_pnl_idr`     = FX move only, on the cost basis.
   - These two must sum to total IDR unrealized P&L (reconciliation check).
5. A ticker with `qty == 0` after processing is a **closed position**
   (contributes to realized P&L only, excluded from current holdings).

## Read behavior & resilience

- Read is **read-only**; the pipeline never writes to the Sheet.
- Blank trailing rows are ignored. Rows missing a required field are **skipped
  with a flagged note** in the report (fail-safe), never crash the run.
- `ticker` values are trimmed and uppercased on read.
- If the Sheet is unreachable, the run aborts the ledger-dependent sections with
  a clear note but still ships macro/opportunity sections (fail-safe).

## De-identification boundary (for the LLM layer)

When positions are passed to the narrative layer, tickers and IDR amounts are
replaced by generic labels and percentages (e.g. "Position A: semiconductor
ETF, 53% of portfolio, −2.2%"). Real amounts never leave the pipeline toward a
third party. See `docs/00-overview/02. Architecture.md`.

## Test cases

Deterministic unit tests over a fixed in-memory ledger (no live Sheet). Each
case gives input rows and the expected derived values.

1. **TC-01 Single BUY → position.** One BUY of qty 2 @ $10 (fee $0). Expect
   `qty = 2`, `avg_cost = 10`, `cost_basis = 20`.
2. **TC-02 Multiple BUYs → weighted average cost.** BUY 1 @ $10, then BUY 3 @
   $20. Expect `qty = 4`, `avg_cost = 17.5`.
3. **TC-03 BUY with fee folds into cost basis.** BUY 2 @ $10, fee $4. Expect
   `avg_cost = 12` (cost basis 24 / 2).
4. **TC-04 Partial SELL → realized P&L, avg cost unchanged.** From TC-02 state
   (qty 4, avg 17.5), SELL 2 @ $25, fee $0. Expect `realized_usd = 15`,
   `qty = 2`, `avg_cost = 17.5`.
5. **TC-05 Full SELL → closed position.** BUY 1 @ $10 then SELL 1 @ $12. Expect
   `qty = 0`, position excluded from current holdings, `realized_usd = 2`.
6. **TC-06 Unrealized P&L (USD).** Hold qty 2, avg $10, current price $9.
   Expect `unrealized_usd = -2`.
7. **TC-07 Currency effect split reconciles.** BUY 1 @ $100 at usdidr 16000;
   current price $100, usdidr_now 17000. Expect `asset_pnl_idr = 0`,
   `fx_pnl_idr = 100000`, and `asset_pnl_idr + fx_pnl_idr` equals total IDR
   unrealized P&L.
8. **TC-08 Rows processed in date order.** Out-of-order rows (later date first)
   produce the same result as chronological order.
9. **TC-09 Malformed row is skipped, not fatal.** A row missing `price_usd` is
   skipped and flagged; remaining valid rows still produce correct positions.
10. **TC-10 Ticker normalization.** `" smh "` is read as `SMH` and aggregates
    with other `SMH` rows.
